# 阶段二：02-需求评审

**目标**：评审需求文档，识别遗漏、矛盾、风险点。

**输入**：`01-需求分析与设计/01-需求记录.md`

**执行方式**：主 Agent 以 reviewer 视角审阅，提出问题，用户逐项确认或驳回（含**澄清复审轮**，见下节）

**🟡 评审必问 4 问模板**（防误升级 / 防漏评审）：

1. **范围**：本次需求覆盖哪些功能 / 数据 / 边界？
2. **边界**：不在范围内的内容是什么？与现有模块如何切分？
3. **风险**：技术风险、数据风险、兼容性风险有哪些？
4. **是否需要 03 方案**：是否超出 🟢 简单预判、需进入 03-技术方案？（第 4 问用于防止 🟡 被误升级到 03）

> 说明：🟢 简单需求采用极简模式（4 问确认，产出独立 `02-需求评审.md`，内容极简 ~200字）；🟡 中等需求必须使用本 4 问模板，但仅确认不列长篇问题清单。

**★ 必须明确（缺失 ⇒ 按 🟡 严重问题登记；未清零不得判"通过（无修改意见）"）**：
1. 做什么（功能点 vs 本次不做）
2. 为谁做（角色 / 场景）
3. 关键业务规则（**以 01 文档 §4.1「业务规则」栏为唯一源**；此处只做缺失校验，不重复定义）
4. 验收标准（可验证判据）

**建议明确（缺失 ⇒ 按 🔵 轻微问题登记，不阻塞）**：实现偏好 / 交互细节 / 性能与兼容性预期 / 文档口径。

### ★ 需求歧义消解（A3 · 极模糊需求）

**判定**：需求存在 ≥2 种合理解释，且不同解释导致范围或验收标准不同。

**动作**：列 2~3 种合理解释 + 各自影响（范围/工作量/风险），请用户选择或补充。
**禁止**：直接驳回；或按 Agent 单方选定的解释推进。

**记录**：§2 问题与处置表记一行（问题=歧义点；处置=用户选定解释及理由）。

### ★ 澄清复审轮（A6 · 收敛判据 + 硬上限 3）

**触发**：用户对 step-1-review 问题的回答**引入新信息 / 改变范围或验收标准** ⇒ 进入复审轮；
连续两轮回答无新增 ⇒ 收敛终止。

**硬上限**：3 轮（首轮 + 复审 ≤2）；达上限仍未收敛 ⇒ 剩余问题转 §4 遗留清单，由用户裁定后放行。
**可回调项**：上限 3 为首版取值（无实测）；若首个迭代出现"3 轮不收敛"即回调。

**🟢 豁免**：简单需求仅 4 问确认，不启复审轮。

**轮次记录**：写入 02 文档头部表格「澄清轮次」行（不新增 state 字段）。

**分域**：本机制仅适用 02 用户澄清链；与 `engine/cross-review-protocol.md` §五「不重启独立 Agent」边界
（交叉审查合并域）**分属两域，勿混**。

### ★ 独立 Agent 规范性前置检查（🔴 应执行 / 🟡 可选）

> 在 step-1-review 之前执行独立 Agent 对需求文档的格式完整性检查（**🔴 复杂级应执行**，🟡 中等级可选）。
> 只检查规范性问题（字段缺失、格式不一致、描述歧义），不评审业务合理性。
> 审查指令模板详见 `engine/cross-review-protocol.md` §4.3。

**★ 两个维度勿混**（口径分层见下）：
- **执行要求**（协议 §二/§七、`phase-steps.md` §阶段二、`SKILL.md` 原则 12）：🔴 复杂级**应执行**、🟡 可选、🟢 跳过
- **门禁强制**（`complexity-scoring.md` §二「步骤 mandatory 默认值表」，**该表为 `mandatory` 的唯一权威源**）：
  本步骤 🟡/🔴 均为 **`mandatory=false`** ⇒ **可选、不阻塞阶段推进**（与 03/04 的交叉审查 `true` 不同）

**适用复杂度**：🔴 应执行 / 🟡 可选（🟢 跳过）；`mandatory=false`（不做不阻塞推进）。

**产出**：`02-需求评审/02-需求评审.md`（模板：`phase-02-需求评审.md`，优先级见启动协议 §模板解析优先级）

> **版式纪律**：产出文档须遵循 `engine/doc-style-guide.md`（问题清单"一行一条"，处置细节进附录）；生成后自检 `python scripts/doc_lint.py <文件>`（ERROR 必修）。

**交付标准**：所有问题已决议（复审轮已收敛或已达上限，剩余问题在 §4 遗留清单），用户确认"评审通过"或"进入技术方案"；**文档版式自检 ERROR 0**（`python scripts/doc_lint.py <文档>`）
★ 等待方式（A/B/D + 时限/退化）见 `engine/waiting-protocol.md`。
