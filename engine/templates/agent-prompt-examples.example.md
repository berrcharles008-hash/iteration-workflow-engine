# Agent Prompt 示例（项目级）

> **本文件为引擎模板**，由 `install.ps1` 复制为 `project/agent-prompt-examples.md`，再由项目填充特有内容。
> **消费点**：04-开发实现 Step 2 派发 Team Agent 前必读（`engine/phase-04.md` §Step 2、`engine/startup-protocol.md` 配置索引）。
> **目的**：让每个 Team Agent 收到的 prompt 结构一致、约束齐全，避免"生成的代码能编译但不能合入"。

---

## ★ 产出落盘红线（04 阶段 Team 派单必含，2026-09-24 新增）

> **起因**：CodeBuddy 扩展宿主过载时会异常终止，终止瞬间 Team 成员与未回传的产出一并丢失
> （平台提示：`extension host terminated unexpectedly ... any team members were stopped`；
> 实测 09-23 / 09-24 共 5 次）。成员"只输出不写文件"⇒ 产出仅存在于回传消息中，必须落盘兜底。

**每个成员 prompt 必须原样包含**【产出落盘】段（模板见 `engine/team-agent-strategy.md` §七）：

- 每完成**一个**文件立即追加写 `.codebuddy/temp/team-out/<成员名>.md`，**不得**最后一次性写
- 原子写：先写 `<成员名>.md.tmp`，再 rename 覆盖（防崩溃产生半截文件）
- 全部完成后追加 `<!-- TEAM-OUT-COMPLETE files=N -->`
- **只落盘产出记录**，不得借机写业务文件

> **边界澄清**：下文示例中的"禁止 write_file / 不写文件"特指**业务代码文件**；
> 产出记录落盘是**强制例外**，成员不得因该禁令拒绝落盘。

---

## 一、通用结构（★ 每个 prompt 必须包含以下 8 段）

| # | 段 | 作用 | 缺失后果 |
|:--:|----|------|----------|
| 1 | **角色与边界** | 明确"只生成代码、不写文件"，禁止顺带重构 | Agent 自行 `write_file` / 改无关文件 |
| 2 | **任务上下文** | 迭代 ID + 工作包 + 任务号 + **验收锚点**（需求/规格条目号） | 代码与验收条件对不上 |
| 3 | **现状代码** | **真实文件路径 + 关键片段**（不要只描述） | Agent 臆造类名/方法名 |
| 4 | **约定与红线** | 指向 `project/coding-conventions.md` + 本项目 3~5 条硬约束 | 编译通过但不符合项目架构 |
| 5 | **交付形式** | 文件路径 + 完整内容（新建）/ diff 片段（修改），不写散文 | 主 Agent 无法批量落地 |
| 6 | **自检清单** | 3~6 条可自证的检查（编译单元注册 / 语法版本 / 命名 / 事务） | 漏项到 05 阶段才暴露 |
| 7 | **反例** | 本项目禁止的 1~3 条具体写法 | 重复历史事故 |
| 8 | **输出模板** | 固定骨架，便于主 Agent 解析汇总 | 汇总成本高 |

## 二、示例模板（复制后替换为项目实际内容）

### 示例 A：后端 —— 新增业务方法 + API 端点

```
你是 {{项目名}} 的后端开发 Agent。

【1. 角色与边界】
- 只生成代码内容，禁止调用 write_file / replace_in_file / execute_command **写业务文件**。
- 产出记录必须落盘到 .codebuddy/temp/team-out/<成员名>.md（原子写：先 .tmp 再 rename）。
- 只改本任务列出的文件；发现无关问题写到输出末尾"备注"，不要动手。

【2. 任务上下文】
- 迭代：{{迭代ID}}  工作包：{{WP编号}}  任务号：{{T编号}}
- 目标：{{一句话目标}}
- 验收锚点：{{规格条目号，如 M8 §4.1 #2 / F2}}

【3. 现状代码】
已有文件（真实路径）：
- {{BLL 文件路径}}   —— Mgr 基类：{{基类名}}
- {{Web 文件路径}}   —— 路由特性：{{[WebApi] / [WebApiMethod]}}
- {{Inf 文件路径}}   —— 接口 / Entity / DTO 位置
关键片段：
{{粘贴 20~40 行真实代码}}

【4. 约定与红线】
- 详见 project/coding-conventions.md（后端部分）。
- 红线：① {{如：新增 .cs 必须同步 .csproj 的 Compile Include}}
        ② {{如：C# 4.0，禁 async/await/插值/nameof/?./HttpClient}}
        ③ {{如：表名列名全大写；查询必带 AND DELETED_MARK = 0}}

【5. 交付形式】
按文件逐个输出：
### 文件：{{相对路径}}  操作：新建/修改  +行数
```{{语言}}
{{完整内容或 diff}}
```

【6. 自检清单】
- [ ] {{如：已在 .csproj 注册编译单元}}
- [ ] {{如：错误码常量集中在指定文件}}
- [ ] {{如：参数化 SQL，无字符串拼接}}

【7. 反例】
- ❌ {{本项目曾踩过的具体写法}}

【8. 输出模板】
## 变更清单
| 文件 | 操作 | 行数 |
## 代码
（按第 5 段格式）
## 自检结果
（逐条 ✓/✗）
## 备注
```

### 示例 B：前端 —— 新增/改造页面

```
你是 {{项目名}} 的前端开发 Agent。

【1. 角色与边界】（同上：只生成代码，不写业务文件）
产出记录须落盘（见「产出落盘红线」）。

【2. 任务上下文】
- 迭代：{{迭代ID}}  任务号：{{T编号}}  原型参照：{{原型文件路径}}
- 验收锚点：{{界面走查 / 具体交互条}}

【3. 现状代码】
- 页面目录：{{pages 路径}}
- 入口：{{entry 路径}} ↔ {{html 路径}}（成对）
- 数据层：{{bll / net 路径}}
关键片段：{{粘贴真实代码}}

【4. 约定与红线】
- 详见 project/coding-conventions.md（前端部分）。
- 红线：① {{如：表格统一 ag-grid-vue，平台不含 el-table}}
        ② {{如：禁写 super.<hook>()}}
        ③ {{如：import 常量须 computed 暴露}}

【5~8 段】同示例 A。
```

## 三、维护约定

- 示例数量：后端 ≥1、前端 ≥1；复杂项目可各 2 个（**新增类** / **改造类**）。
- 每次 04 阶段结束后，把"Agent 实际踩的坑"回写到对应示例的【反例】段。
- **04 阶段每个成员 prompt 必须包含【产出落盘】段**（见文首「产出落盘红线」），挂进【1. 角色与边界】；漏派即视为未完成 Step 2。
- 通用机制（8 段结构、**产出落盘红线**）在**引擎侧**维护；项目特有内容（红线 / 路径 / 反例）在 **`project/` 侧**维护。
